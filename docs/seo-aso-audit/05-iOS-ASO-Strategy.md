## 1. Metadata Fields

### App Name (28/30 chars)
```
DateMeUp- Date Night Planner
```
The hyphen-space after "DateMeUp" is intentional — it creates a natural visual separator without costing extra character weight. The phrase "Date Night Planner" doubles as a keyword that users actually search.

### Subtitle (27/30 chars)
```
Vote on Date Night Together
```
Avoids repeating keywords already in the name (`date`, `night`). Introduces `vote` and `together` — high-intent, low-competition terms not in the primary name.

### Keywords Field (86/100 chars)
```
date,night,couples,planner,ideas,romantic,together,voting,activities,group,outing,plan
```
Rules followed:
- No spaces after commas (Apple's parser is strict — a space = wasted character)
- No words already in the App Name or Subtitle (those are indexed automatically)
- No plural/singular duplicates (Apple indexes both forms)
- Ordered roughly by volume × relevance

**Keyword rationale:**
| Keyword | Rationale |
|---------|-----------|
| `date` | Core term, high volume |
| `night` | Core modifier |
| `couples` | Primary audience identifier |
| `planner` | Utility searchers — high intent |
| `ideas` | "date ideas" is a top query |
| `romantic` | Differentiates from group apps |
| `together` | Collaborative feature signal |
| `voting` | Unique mechanic, niche but precise |
| `activities` | "date activities" / "couple activities" |
| `group` | Secondary audience (friend groups) |
| `outing` | "group outing" modifier |
| `plan` | Verb form — "plan a date" queries |

**Terms intentionally excluded** (in Name or Subtitle, so auto-indexed):
- `DateMeUp`, `Date Night`, `Vote`

**Terms excluded** (off-brand risk):
- `dating`, `match`, `meet`, `singles` — these signal a dating app for strangers, which DateMeUp is not.

## 7. App Store Search Discoverability Mechanics (2026)

### How Apple Search Works
- Apple's algorithm indexes: **App Name, Subtitle, Keywords field** (all three equally). The full description is **not** indexed for search ranking.
- **Keyword authority** accrues over time — apps with consistent ratings/engagement on a keyword outrank newer apps even with identical metadata.
- **Category browse** (Today tab, Charts) is driven by: download velocity, rating score × volume, engagement signals (session length, retention).

### 2026-Specific Signals
- **App clips** now influence discoverability — consider building a clip for the Guest Vote flow (no install required, perfect for sharing).
- **AI-powered search refinement** (introduced iOS 17.4+): Apple's on-device search now surfaces apps based on semantic intent, not just keyword matching. Descriptions that clearly explain *what the user does* in the app rank better for semantic queries like "what should we do tonight couple".
- **Trending searches** in App Store → target seasonal spikes (Valentine's Day, New Year's Eve, summer weekends) with In-App Events and Promotional Text updates.

### Category Ranking Strategy
- **Social Networking** charts are heavily dominated by giants (Instagram, TikTok, Snapchat). Don't target Top Overall charts — target **Top Charts within subcategory** or **Editors' Choice** pitches.
- File for **editorial consideration** via App Store Connect → Promote Your App. Best timing: major feature releases, Valentine's Day, New Year. Pitch: "First voting-based date night planner — solves the universal couple's dilemma."
- **New App** badge (first 30 days) boosts visibility on category browse — ensure launch metadata is optimised before Day 1.

## 8. Ratings and Review Strategy

### When to Prompt
**Trigger:** After the Match celebration screen — the "It's a Match!" moment is the highest-delight point in the user journey. This is when users are most likely to rate 5 stars.

**Implementation:** Use `SKStoreReviewRequest.requestReview()` (iOS native) wrapped in Expo's `expo-store-review`.

```typescript
// Trigger after match is displayed, with a 1.5s delay for celebration animation to complete
import * as StoreReview from 'expo-store-review';

const promptForReview = async () => {
  const isAvailable = await StoreReview.isAvailableAsync();
  if (isAvailable) {
    await new Promise(resolve => setTimeout(resolve, 1500));
    await StoreReview.requestReview();
  }
};
```

### Rules (Apple enforces strictly)
- Maximum **3 prompts per 365 days** per user — Apple hard-limits this
- Never prompt after an error, cancellation, or negative experience
- Never use custom "rate us" screens — Apple rejects apps that gate the native prompt behind their own UI

### Review Velocity Targets
| Phase | Target |
|-------|--------|
| Launch (0–30 days) | 10+ ratings, ≥4.5 avg |
| 90 days | 50+ ratings |
| 6 months | 200+ ratings, ≥4.7 avg |

A sub-4.0 rating triggers search ranking suppression. Monitor App Store Connect daily in the first 30 days.

### Responding to Reviews
- Respond to every 1-star and 2-star review within 48 hours via App Store Connect
- Responses are public and signal responsiveness to Apple's editorial team
- Template for negative reviews: acknowledge → explain what's fixed or coming → invite back

## 9. A/B Testing (Product Page Optimization)

App Store Connect offers **Product Page Optimization** — A/B test up to 3 variants of icon, screenshots, and App Preview simultaneously.

**Recommended first test:** Screenshot order — test whether leading with the "Match!" celebration (emotional hook) outperforms leading with the problem frame (rational hook).

**Minimum sample:** 90 days or 5,000 impressions per variant for statistical significance.
